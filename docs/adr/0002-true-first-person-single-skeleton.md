# True first-person, single skeleton (confirmed already in place)

We originally planned to replace a classic arms-viewmodel/third-person-mesh split with one full-body skeleton per Combatant. On inspection, that work doesn't need doing: this project's template (UE 5.4+'s First Person Template) already implements exactly that, via Epic's `FirstPersonPrimitiveType` system. `Asword_ue5_8Character` has two `USkeletalMeshComponent`s — `FirstPersonMesh` (tagged `EFirstPersonPrimitiveType::FirstPerson`) and the inherited body mesh from `ACharacter::GetMesh()` (tagged `EFirstPersonPrimitiveType::WorldSpaceRepresentation`) — but both reference the *same* skeletal mesh asset (`SKM_Manny_Simple`), kept in sync via a Copy Pose animation blueprint (`ABP_FP_Copy`). The `FirstPerson`-tagged component just gets separate FOV/near-clip handling for the local view; it isn't a distinct arms-only rig. The camera is already attached at that mesh's `head` bone.

Net effect: this is the "one full-body skeleton, camera at an eye bone" outcome we wanted, achieved by the engine's own modern first-person rendering feature rather than something we need to build. `sword_ue5_8Character.h`'s comment calling `FirstPersonMesh` an "arms" mesh was a stale leftover from the classic template pattern and has been corrected — it's the full body, not arms-only.
